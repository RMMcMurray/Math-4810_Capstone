1 Overview

This notebook reruns the linear-model search from Model Building 3 with two big constraints added to make the final model usable as a self-service price predictor:

  1. No assessor-derived values. Land Value and Total Value come from the county assessor; a prospective buyer or seller cannot provide those numbers without already knowing the likely sale price. Both columns are dropped before any model is fit.
  2. No composite “weighted” scores the owner cannot self-report. The only weighted variable the model keeps is EffYearBuilt_Weighted — the effective year built is a concrete property fact that a user can reasonably provide. Quality_Weighted and BsmtFinishPct_Weighted both require assessor-grade judgment or detailed basement measurements that a typical user doesn’t have, so they are also dropped.

With that smaller feature set, the search loop is identical to Model Building 3:

  1. Reload and clean the raw CSV; drop the four newly-excluded columns on top of the usual leakage / count columns.
  2. Re-derive the row-drop budget from scratch on the new feature set using influence diagnostics (Cook’s D, studentized residuals).
  3. Split train/test (80/20, random_state=2026).
  4. Fit OLS / Ridge / Lasso / ElasticNet / Huber / WLS / Quantile / PCR / PLS / segment-stratified variants with and without polynomial and segment-interaction terms.
  5. Rank by test R², then re-fit the winner for full inference.
  6. Ship a predict_price(**features) helper that takes plain user-facing feature names and returns a dollar prediction plus 95% confidence / prediction intervals.

The final section shows the predictor in action on a few example properties.

6 Feature-Engineering Helpers

The three heavy-tail continuous features — ln_GLA, EffYearBuilt_Weighted, and AsinH_Acreage — each get a squared term, and each segment_* dummy gets multiplied by those same three numerics.

Code 
POLY_COLS   = ['ln_GLA', 'EffYearBuilt_Weighted', 'AsinH_Acreage']
KEY_NUMERIC = ['ln_GLA', 'EffYearBuilt_Weighted', 'AsinH_Acreage']
seg_cols    = [c for c in X_train.columns if c.startswith('segment_')]

def build_poly_seg(X_in, ref_cols=None):
    X2 = X_in.copy()
    for c in POLY_COLS:
        if c in X2.columns:
            X2[f'{c}_sq'] = X2[c] ** 2
    for sc in seg_cols:
        for kn in KEY_NUMERIC:
            if kn in X2.columns:
                X2[f'{sc}_x_{kn}'] = X2[sc] * X2[kn]
    if ref_cols is not None:
        X2 = X2.reindex(columns=ref_cols, fill_value=0)
    return X2

X_train_v2 = X_train.copy()
X_test_v2  = X_test.copy()
for c in POLY_COLS:
    if c in X_train_v2.columns:
        X_train_v2[f'{c}_sq'] = X_train_v2[c] ** 2
        X_test_v2[f'{c}_sq']  = X_test_v2[c]  ** 2

def run_wls(X_in_tr, X_in_te, label):
    Xc_tr = sm.add_constant(X_in_tr, has_constant='add')
    Xc_te = sm.add_constant(X_in_te, has_constant='add').reindex(
                columns=Xc_tr.columns, fill_value=0)

    # Stage 1 — OLS to estimate variance structure
    ols_s1 = sm.OLS(y_train, Xc_tr).fit()
    fv     = ols_s1.predict(Xc_tr).values
    res_s1 = y_train.values - fv

    # log(|resid|²) ≈ function of fitted values → exp gives σ²
    var_model = sm.OLS(np.log(res_s1 ** 2 + 1e-8),
                        sm.add_constant(fv)).fit()
    w = 1.0 / np.exp(var_model.predict(sm.add_constant(fv)))

    wls = sm.WLS(y_train, Xc_tr, weights=w).fit()
    yhat_tr, yhat_te = wls.predict(Xc_tr), wls.predict(Xc_te)
    r2_tr, r2_te = r2_score(y_train, yhat_tr), r2_score(y_test, yhat_te)

    print("=" * 55)
    print(f"  {label}")
    print("=" * 55)
    print(f"  Train R² / Test R² : {r2_tr:.4f}  /  {r2_te:.4f}")
    print(f"  Train–Test gap     : {r2_tr - r2_te:+.4f}")

    record(model=label, r2_train=r2_tr, r2_test=r2_te, n_feat=X_in_tr.shape[1])
    return wls

14.3 Assumption Check — What Passes and What Doesn’t

  • Linearity — the residuals-vs-fitted cloud is centered on zero across the fitted range. There’s mild funneling at the low end (small / cheap land sales), but no clear curvature. ✅
  • Independence — Durbin-Watson ≈ 2.00. ✅
  • Normality of residuals — skew essentially zero; kurtosis slightly leptokurtic (~2.1). The Q-Q plot is straight through the body with a bit of tail deviation. ✅ reasonable.
  • Homoscedasticity — Breusch-Pagan p ≈ 0. ❌ As in Model Building 3, residual variance grows with the fitted value. Classical OLS point predictions remain unbiased; only the standard errors are affected, and robust (HC3) SEs are a one-liner away if you need them: winner.get_robustcov_results('HC3').summary().

Without the assessor’s Total Value anchoring the model, the heteroscedasticity pattern is slightly more pronounced at the low end, but the center of the fit is still unbiased and the practical test R² (0.79) is in workable territory for user-facing predictions.

14.4 What The Model Is Saying

The largest-magnitude coefficients (by |t|) trace to four intuitive sources:

  1. Above-ground living area — ln_GLA is by far the strongest predictor; doubling GLA multiplies predicted price by roughly a factor tied to the ln_GLA coefficient (≈0.22). Exactly as expected.
  2. Effective year built — newer / better-maintained properties command a premium, captured here by EffYearBuilt_Weighted.
  3. Acreage — AsinH_Acreage is strongly positive for land sales; the segment_Residential and segment_Multi-Family dummies pick up the type-specific discounts/premia that wrap around the acreage signal.
  4. Property-type and style dummies — SpecificPropTypeDescription_*, Main_StyleDesc_*, and NbhdCode2_* together absorb the residual categorical fixed effects.

Notably absent: since the model has no engineered interactions, every coefficient can be read one-at-a-time. That’s the trade-off — Lasso→OLS (poly+seg×num) had a slightly lower AIC but a lower test R² and introduced interaction terms that make the predictor harder to explain to a non-technical user.

14.5 Back-Transforming To Dollars

On the log scale the test MAE is ≈0.089. In dollar terms that’s

\[ \text{mean test } \$ \text{ error} \approx \overline{P_{\text{test}}} \cdot \left(e^{0.089} - 1\right) \]

which on this test set with a mean sale price near $412K comes out to roughly $38K, or ~9.3% of mean price. That’s a reasonable error band for a user-facing predictor that uses only what a property owner can self-report.

def predict_price(**features):
    """
    Predict residential / land / multi-family property price from user-
    provided features, using the Lasso→OLS (base, no assessor) winner.

    Recognized numeric inputs (pass raw values, not transformed):
        GLA                      — above-grade living area, sq ft
        Acreage                  — land area, acres
        Tot_Bsmt                 — total basement sq ft
        EffYearBuilt_Weighted    — effective year built (weighted)
        GarageArea               — attached garage sq ft
        CarportArea              — attached carport sq ft
        SqFt_DetGarage           — detached garage sq ft
        SqFt_DetCarport          — detached carport sq ft
        Sqft_Barn                — barn sq ft
        SqFt_Guest_House         — guest-house sq ft
        SqFt_Pools               — pool(s) sq ft
        SqFt_Recreational_Courts — court(s) sq ft
        SqFt_Shed                — shed(s) sq ft
        SqFt_Gazebo_Pavilion     — gazebo / pavilion sq ft
        FullBaths_Total          — full bathrooms
        HalfBaths_Total          — half bathrooms
        KitchenCount             — kitchens
        Laundry_Count            — laundry rooms
        GarageCapacity           — cars the garage holds
        CarportCapacity          — cars the carport holds

    Recognized categorical inputs (use values from AVAILABLE_LEVELS above):
        segment, PropTypeDescription, SpecificPropTypeDescription,
        NbhdCode2, Main_StyleDesc

    Missing numeric features fall back to the segment median (so a land sale
    with no building still gets sensible EffYearBuilt / ln_GLA defaults).
    Missing categoricals fall back to the reference (dropped) level.

    Returns
    -------
    dict with keys:
        predicted_price  — point estimate in dollars
        ln_price         — same on the log scale
        ci_low / ci_high — 95% confidence interval for the mean
        pi_low / pi_high — 95% prediction interval for a single observation
    """
    seg      = features.get('segment', 'Residential')
    seg_def  = SEG_DEFAULTS.get(seg, SEG_DEFAULTS.get('Residential', {}))

    row = {c: 0 for c in BASE_COLS}

    # Pre-fill with segment medians for the continuous features most likely to
    # be missing (esp. land sales with no building).
    for k, v in seg_def.items():
        if k in row:
            row[k] = v

    # ── Integer-count features passed straight through ─────────────────────
    for col in ['FullBaths_Total', 'HalfBaths_Total', 'KitchenCount',
                'Laundry_Count', 'GarageCapacity', 'CarportCapacity']:
        if col in features and col in row:
            row[col] = float(features[col])

    if 'EffYearBuilt_Weighted' in features and 'EffYearBuilt_Weighted' in row:
        row['EffYearBuilt_Weighted'] = float(features['EffYearBuilt_Weighted'])

    # ── Log-GLA (only if user supplies a positive GLA) ─────────────────────
    if 'GLA' in features and 'ln_GLA' in row:
        gla = float(features['GLA'])
        if gla > 0:
            row['ln_GLA'] = np.log(gla)

    # ── arcsinh-transformed continuous features ────────────────────────────
    asinh_map = {
        'Acreage'                 : 'AsinH_Acreage',
        'Tot_Bsmt'                : 'AsinH_Tot_Bsmt',
        'CarportArea'             : 'AsinH_Carport_Area',
        'GarageArea'              : 'AsinH_Garage_Area',
        'SqFt_DetGarage'          : 'AsinH_SqFt_Det_Garage',
        'SqFt_DetCarport'         : 'AsinH_SqFt_Det_Carport',
        'Sqft_Barn'               : 'AsinH_SqFt_Barn',
        'SqFt_Guest_House'        : 'AsinH_SqFt_Guest_House',
        'SqFt_Pools'              : 'AsinH_SqFt_Pools',
        'SqFt_Recreational_Courts': 'AsinH_SqFt_Recreational_Courts',
        'SqFt_Shed'               : 'AsinH_SqFt_Shed',
        'SqFt_Gazebo_Pavilion'    : 'AsinH_SqFt_Gazebo_Pavilion',
    }
    for raw, enc in asinh_map.items():
        if raw in features and enc in row:
            row[enc] = float(np.asinh(float(features[raw])))

    # ── Categorical → dummy flags ──────────────────────────────────────────
    for cat in DUMMY_COLS:
        val = features.get(cat, None)
        if val is None: continue
        dummy = f'{cat}_{val}'
        if dummy in row:
            row[dummy] = 1
        # if val == reference level, no dummy is set (that's correct)

    # ── Build the feature vector in the exact training column order ────────
    X_new   = pd.DataFrame([row])[BASE_COLS]
    X_new_s = X_new[sel_names]
    X_new_c = sm.add_constant(X_new_s, has_constant='add').reindex(
                columns=Xc_tr.columns, fill_value=0)

    # ── Get point prediction plus 95% mean & observation intervals ─────────

        'ln_price'       : ln_pred,
        'ci_low'         : float(np.exp(ln_ci_low)),
        'ci_high'        : float(np.exp(ln_ci_high)),

A couple of notes on using the helper in practice:

  • The 95% CI (confidence interval for the mean) is the band for where the average sale price of properties with these exact features is expected to fall — typically tight, a few percent wide.
  • The 95% PI (prediction interval for a single sale) is the band you actually want if you’re predicting one specific property’s sale price — wider, because it includes individual-sale variability on top of the mean uncertainty.
  • If the caller mis-types a categorical level (say, 'C' vs. 'c') the corresponding dummy never activates and the prediction silently collapses toward the reference level. Check the AVAILABLE_LEVELS print-out above for valid spellings.
  • The function is intentionally permissive about unused kwargs, so passing an extra field the model doesn’t know is a no-op rather than an error.

# Overview

This notebook reruns the linear-model search from *Model Building 3* with
two big constraints added to make the final model usable as a
self-service price predictor:

1.  **No assessor-derived values.**  `Land Value` and `Total Value` come
    from the county assessor; a prospective buyer or seller cannot
    provide those numbers without already knowing the likely sale price.
    Both columns are dropped before any model is fit.
2.  **No composite "weighted" scores the owner cannot self-report.**
    The only weighted variable the model keeps is
    `EffYearBuilt_Weighted` — the effective year built is a concrete
    property fact that a user can reasonably provide.
    `Quality_Weighted` and `BsmtFinishPct_Weighted` both require
    assessor-grade judgment or detailed basement measurements that a
    typical user doesn't have, so they are also dropped.

With that smaller feature set, the search loop is identical to Model
Building 3:

1.  Reload and clean the raw CSV; drop the four newly-excluded columns
    on top of the usual leakage / count columns.
2.  **Re-derive the row-drop budget from scratch** on the new feature
    set using influence diagnostics (Cook's D, studentized residuals).
3.  Split train/test (80/20, `random_state=2026`).
4.  Fit OLS / Ridge / Lasso / ElasticNet / Huber / WLS / Quantile /
    PCR / PLS / segment-stratified variants with and without polynomial
    and segment-interaction terms.
5.  Rank by test R², then re-fit the winner for full inference.
6.  **Ship a `predict_price(**features)` helper** that takes plain
    user-facing feature names and returns a dollar prediction plus 95%
    confidence / prediction intervals.

The final section shows the predictor in action on a few example
properties.

## WLS (Variance-Structure Weights)

```{python}
#| label: wls

def run_wls(X_in_tr, X_in_te, label):
    Xc_tr = sm.add_constant(X_in_tr, has_constant='add')
    Xc_te = sm.add_constant(X_in_te, has_constant='add').reindex(
                columns=Xc_tr.columns, fill_value=0)

    # Stage 1 — OLS to estimate variance structure
    ols_s1 = sm.OLS(y_train, Xc_tr).fit()
    fv     = ols_s1.predict(Xc_tr).values
    res_s1 = y_train.values - fv

    # log(|resid|²) ≈ function of fitted values → exp gives σ²
    var_model = sm.OLS(np.log(res_s1 ** 2 + 1e-8),
                        sm.add_constant(fv)).fit()
    w = 1.0 / np.exp(var_model.predict(sm.add_constant(fv)))

    wls = sm.WLS(y_train, Xc_tr, weights=w).fit()
    yhat_tr, yhat_te = wls.predict(Xc_tr), wls.predict(Xc_te)
    r2_tr, r2_te = r2_score(y_train, yhat_tr), r2_score(y_test, yhat_te)

    print("=" * 55)
    print(f"  {label}")
    print("=" * 55)
    print(f"  Train R² / Test R² : {r2_tr:.4f}  /  {r2_te:.4f}")
    print(f"  Train–Test gap     : {r2_tr - r2_te:+.4f}")

    record(model=label, r2_train=r2_tr, r2_test=r2_te, n_feat=X_in_tr.shape[1])
    return wls
```

## What The Model Is Saying

The largest-magnitude coefficients (by |t|) trace to four intuitive
sources:

1.  **Above-ground living area** — `ln_GLA` is by far the strongest
    predictor; doubling GLA multiplies predicted price by roughly a
    factor tied to the `ln_GLA` coefficient (≈0.22).  Exactly as
    expected.
2.  **Effective year built** — newer / better-maintained properties
    command a premium, captured here by `EffYearBuilt_Weighted`.
3.  **Acreage** — `AsinH_Acreage` is strongly positive for land sales;
    the `segment_Residential` and `segment_Multi-Family` dummies pick
    up the type-specific discounts/premia that wrap around the acreage
    signal.
4.  **Property-type and style dummies** — `SpecificPropTypeDescription_*`,
    `Main_StyleDesc_*`, and `NbhdCode2_*` together absorb the residual
    categorical fixed effects.

Notably absent: since the model has no engineered interactions, every
coefficient can be read one-at-a-time.  That's the trade-off —
`Lasso→OLS (poly+seg×num)` had a slightly lower AIC but a lower test R²
and introduced interaction terms that make the predictor harder to
explain to a non-technical user.


## Back-Transforming To Dollars

On the log scale the test MAE is ≈0.089.  In dollar terms that's

$$
\text{mean test } \$ \text{ error} \approx \overline{P_{\text{test}}} \cdot \left(e^{0.089} - 1\right)
$$

which on this test set with a mean sale price near \$412K comes out to
roughly \$38K, or ~9.3% of mean price.  That's a reasonable error band
for a user-facing predictor that uses only what a property owner can
self-report.


# Predictor Helper — `predict_price(**features)`

This is the entire point of dropping the assessor values: the trained
model can be wrapped in a simple function that accepts user-facing
feature names, applies the same transforms we used in training, builds
the dummy encoding, and returns a dollar prediction with 95% mean- and
observation-interval bands.

```{python}
#| label: predict_helpers_setup

# ══════════════════════════════════════════════════════════════════════════════
# Segment-aware defaults — when a user doesn't supply a numeric feature
# (common for Land Sales where no building exists), we fall back to the
# training-set median for that segment.  Without this, setting e.g.
# EffYearBuilt_Weighted = 0 for a land sale produces a wildly negative
# ln-price prediction.
# ══════════════════════════════════════════════════════════════════════════════
SEG_DEFAULTS = {}
for seg, sub in df_copy.groupby('segment'):
    SEG_DEFAULTS[seg] = {
        'ln_GLA'               : float(sub['ln_GLA'].median()),
        'EffYearBuilt_Weighted': float(sub['EffYearBuilt_Weighted'].median()),
        'AsinH_Tot_Bsmt'       : float(sub['AsinH_Tot_Bsmt'].median()),
        'AsinH_Acreage'        : float(sub['AsinH_Acreage'].median()),
        'AsinH_Garage_Area'    : float(sub['AsinH_Garage_Area'].median()),
        'AsinH_Carport_Area'   : float(sub['AsinH_Carport_Area'].median()),
    }

# Which dummy level was dropped as reference (= implicit baseline)?
DUMMY_REFERENCE = {}
for col in DUMMY_COLS:
    if col not in df_copy.columns: continue
    all_levels = sorted(df_copy[col].dropna().unique().tolist())
    encoded    = [c for c in X_train.columns if c.startswith(f'{col}_')]
    kept       = [c.replace(f'{col}_', '') for c in encoded]
    dropped    = [lv for lv in all_levels if lv not in kept]
    DUMMY_REFERENCE[col] = dropped[0] if dropped else None

# Cache the column order / encoded levels / available categorical values
BASE_COLS           = X_train.columns.tolist()
AVAILABLE_LEVELS    = {c: sorted(df_copy[c].dropna().unique().tolist())
                       for c in DUMMY_COLS if c in df_copy.columns}

print("Available categorical values (pass these into predict_price):")
for c, lvls in AVAILABLE_LEVELS.items():
    ref = DUMMY_REFERENCE.get(c, None)
    print(f"  {c}  (reference={ref})")
    for lv in lvls:
        marker = " ← reference" if lv == ref else ""
        print(f"      - {lv}{marker}")
```

```{python}
#| label: predict_price_definition

def predict_price(**features):
    """
    Predict residential / land / multi-family property price from user-
    provided features, using the Lasso→OLS (base, no assessor) winner.

    Recognized numeric inputs (pass raw values, not transformed):
        GLA                      — above-grade living area, sq ft
        Acreage                  — land area, acres
        Tot_Bsmt                 — total basement sq ft
        EffYearBuilt_Weighted    — effective year built (weighted)
        GarageArea               — attached garage sq ft
        CarportArea              — attached carport sq ft
        SqFt_DetGarage           — detached garage sq ft
        SqFt_DetCarport          — detached carport sq ft
        Sqft_Barn                — barn sq ft
        SqFt_Guest_House         — guest-house sq ft
        SqFt_Pools               — pool(s) sq ft
        SqFt_Recreational_Courts — court(s) sq ft
        SqFt_Shed                — shed(s) sq ft
        SqFt_Gazebo_Pavilion     — gazebo / pavilion sq ft
        FullBaths_Total          — full bathrooms
        HalfBaths_Total          — half bathrooms
        KitchenCount             — kitchens
        Laundry_Count            — laundry rooms
        GarageCapacity           — cars the garage holds
        CarportCapacity          — cars the carport holds

    Recognized categorical inputs (use values from AVAILABLE_LEVELS above):
        segment, PropTypeDescription, SpecificPropTypeDescription,
        NbhdCode2, Main_StyleDesc

    Missing numeric features fall back to the segment median (so a land sale
    with no building still gets sensible EffYearBuilt / ln_GLA defaults).
    Missing categoricals fall back to the reference (dropped) level.

    Returns
    -------
    dict with keys:
        predicted_price  — point estimate in dollars
        ln_price         — same on the log scale
        ci_low / ci_high — 95% confidence interval for the mean
        pi_low / pi_high — 95% prediction interval for a single observation
    """
    seg      = features.get('segment', 'Residential')
    seg_def  = SEG_DEFAULTS.get(seg, SEG_DEFAULTS.get('Residential', {}))

    row = {c: 0 for c in BASE_COLS}

    # Pre-fill with segment medians for the continuous features most likely to
    # be missing (esp. land sales with no building).
    for k, v in seg_def.items():
        if k in row:
            row[k] = v

    # ── Integer-count features passed straight through ─────────────────────
    for col in ['FullBaths_Total', 'HalfBaths_Total', 'KitchenCount',
                'Laundry_Count', 'GarageCapacity', 'CarportCapacity']:
        if col in features and col in row:
            row[col] = float(features[col])

    if 'EffYearBuilt_Weighted' in features and 'EffYearBuilt_Weighted' in row:
        row['EffYearBuilt_Weighted'] = float(features['EffYearBuilt_Weighted'])

    # ── Log-GLA (only if user supplies a positive GLA) ─────────────────────
    if 'GLA' in features and 'ln_GLA' in row:
        gla = float(features['GLA'])
        if gla > 0:
            row['ln_GLA'] = np.log(gla)

    # ── arcsinh-transformed continuous features ────────────────────────────
    asinh_map = {
        'Acreage'                 : 'AsinH_Acreage',
        'Tot_Bsmt'                : 'AsinH_Tot_Bsmt',
        'CarportArea'             : 'AsinH_Carport_Area',
        'GarageArea'              : 'AsinH_Garage_Area',
        'SqFt_DetGarage'          : 'AsinH_SqFt_Det_Garage',
        'SqFt_DetCarport'         : 'AsinH_SqFt_Det_Carport',
        'Sqft_Barn'               : 'AsinH_SqFt_Barn',
        'SqFt_Guest_House'        : 'AsinH_SqFt_Guest_House',
        'SqFt_Pools'              : 'AsinH_SqFt_Pools',
        'SqFt_Recreational_Courts': 'AsinH_SqFt_Recreational_Courts',
        'SqFt_Shed'               : 'AsinH_SqFt_Shed',
        'SqFt_Gazebo_Pavilion'    : 'AsinH_SqFt_Gazebo_Pavilion',
    }
    for raw, enc in asinh_map.items():
        if raw in features and enc in row:
            row[enc] = float(np.asinh(float(features[raw])))

    # ── Categorical → dummy flags ──────────────────────────────────────────
    for cat in DUMMY_COLS:
        val = features.get(cat, None)
        if val is None: continue
        dummy = f'{cat}_{val}'
        if dummy in row:
            row[dummy] = 1
        # if val == reference level, no dummy is set (that's correct)

    # ── Build the feature vector in the exact training column order ────────
    X_new   = pd.DataFrame([row])[BASE_COLS]
    X_new_s = X_new[sel_names]
    X_new_c = sm.add_constant(X_new_s, has_constant='add').reindex(
                columns=Xc_tr.columns, fill_value=0)

    # ── Get point prediction plus 95% mean & observation intervals ─────────
    pred                   = winner.get_prediction(X_new_c)
    ln_pred                = float(pred.predicted_mean[0])
    ln_ci_low, ln_ci_high  = pred.conf_int(alpha=0.05)[0]
    ln_pi_low, ln_pi_high  = pred.conf_int(obs=True, alpha=0.05)[0]

    return {
        'predicted_price': float(np.exp(ln_pred)),
        'ln_price'       : ln_pred,
        'ci_low'         : float(np.exp(ln_ci_low)),
        'ci_high'        : float(np.exp(ln_ci_high)),
        'pi_low'         : float(np.exp(ln_pi_low)),
        'pi_high'        : float(np.exp(ln_pi_high)),
    }
```

A couple of notes on using the helper in practice:

-   The **95% CI** (confidence interval for the *mean*) is the band for
    where the average sale price of properties with these exact features
    is expected to fall — typically tight, a few percent wide.
-   The **95% PI** (prediction interval for a *single* sale) is the band
    you actually want if you're predicting one specific property's sale
    price — wider, because it includes individual-sale variability on
    top of the mean uncertainty.
-   If the caller mis-types a categorical level (say, `'C'` vs. `'c'`)
    the corresponding dummy never activates and the prediction silently
    collapses toward the reference level.  Check the
    `AVAILABLE_LEVELS` print-out above for valid spellings.
-   The function is intentionally permissive about *unused* kwargs, so
    passing an extra field the model doesn't know is a no-op rather
    than an error.
